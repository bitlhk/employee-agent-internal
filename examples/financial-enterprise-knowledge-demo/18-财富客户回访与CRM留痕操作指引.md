# 财富客户回访与 CRM 留痕操作指引（演示）

> 文件编号：LG-WM-OPS-001
> 版本：V1.0
> 归口部门：零售财富管理部、运营管理部（演示）
> 生效日期：2026-08-01
> 密级：内部

## 1. 适用范围

适用于财富经理完成客户拜访、电话回访、产品到期沟通、投诉跟进和资产配置沟通后的 CRM 记录与后续任务创建。

## 2. 前置条件

- 当前用户和客户归属已核验；
- 回访事实来自本人本次服务过程或企业系统；
- 记录目的、客户标识、联系方式和计划时间已确认；
- CRM 写能力已授权，并具备操作确认和幂等保护。

## 3. 操作步骤

### 3.1 整理事实

区分客户原话、已确认事实、财富经理判断和后续建议。无法确认的信息标记“待核实”，不得改写成客户承诺。

### 3.2 形成回访摘要

摘要应包含沟通时间、方式、目标、核心内容、客户反馈、风险提示和未决事项。不得写入与任务无关的敏感信息。

### 3.3 创建跟进任务

任务至少包含：客户标识、任务类型、标题、计划完成时间、责任人、摘要、数据来源和幂等键。正式写入前向用户展示即将创建的内容并获得必要确认。

### 3.4 核对执行回执

执行后核对 CRM 记录编号和状态。网络超时但结果不确定时，先使用幂等键查询，不得直接重复提交。

## 4. 必查项清单

- [ ] 客户归属通过
- [ ] 沟通事实与判断已区分
- [ ] 计划时间明确且合理
- [ ] 责任人属于可选范围
- [ ] 未记录无关敏感信息
- [ ] 写入前已确认
- [ ] 幂等键稳定且与业务动作绑定
- [ ] 下游回执已保存

## 5. 禁止项

- 不得伪造客户沟通、同意或承诺；
- 不得将模型生成摘要直接标记为客户原话；
- 不得绕过人工确认批量创建任务；
- 不得在超时后更换幂等键盲目重试；
- 不得删除失败或拒绝记录以制造完成状态。

## 6. 异常处理与升级

| 情形 | 处理 |
|---|---|
| CRM 不可用 | 保留内部草稿，明确“未写入”，稍后重试 |
| 执行结果不确定 | 使用原幂等键查询状态 |
| 客户归属变化 | 停止写入，转客户管理岗确认 |
| 涉及投诉或重大风险 | 转消保、合规或主管处理 |
| 用户拒绝确认 | 保留草稿，不执行外部写入 |

## 7. 会后留痕

记录请求人、客户、任务内容指纹、确认人、确认时间、幂等键、Policy Decision、CRM 回执和最终状态。客户完整沟通内容仅按企业保留政策存放在授权系统。
