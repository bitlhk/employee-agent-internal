# 车险产品匹配与方案说明作业规程（演示）

> 文件编号：LG-IA-SOP-003
> 版本：V1.0
> 归口部门：车险产品部（演示）
> 生效日期：2026-08-11
> 密级：内部

## 1. 适用范围

用于将客户和车辆事实与产品 MCP 返回的示范产品进行匹配，形成内部候选方向和说明材料。本规程不提供真实报价，不代替企业产品准入、承保和销售系统。

## 2. 前置条件

1. 当前保险顾问身份和客户归属已通过；
2. 车辆类型、使用性质和主要需求可以核验；
3. 产品来自当前产品 MCP；
4. 产品详情和数据版本可以定位；
5. 所用岗位知识处于有效状态。

## 3. 标准步骤

### 3.1 获取候选产品

使用产品列表或搜索工具获取产品，不得从 Skill 静态清单、网页搜索或模型参数知识补充正式候选。

### 3.2 核验产品事实

读取产品详情，至少核验产品类别、定位、目标人群、保障责任、限制、适用车辆和使用性质。缺少当前状态、渠道或版本时，不得表述为“当前可投保”。

### 3.3 执行硬性筛选

进入正式候选前检查：

- 车辆类型匹配；
- 新能源属性匹配；
- 家用或营运性质匹配；
- 产品状态和渠道可用；
- 关键告知信息完整；
- 当前岗位和组织有权使用该产品资料。

硬性条件不得由模型覆盖。首期 Mock MCP 缺少某些字段时，只能形成“演示候选方向”。

### 3.4 形成匹配解释

每个候选同时说明：

- 客户或车辆侧依据；
- 产品侧依据；
- 可以解决的保障问题；
- 主要限制和待核实事项；
- 为什么未选择其他方向。

### 3.5 形成方案说明

方案以保障结构和候选方向为主。具体保费、折扣、承保条件和最终条款必须进入正式系统或人工流程。

## 4. 必查项

- [ ] 客户事实来自授权 MCP
- [ ] 产品事实来自产品 MCP
- [ ] 产品详情和数据时间已披露
- [ ] 车辆使用性质已核验
- [ ] 营运车辆未按普通家用车辆处理
- [ ] 未编造价格、优惠或在售状态
- [ ] 候选包含限制和待核实事项
- [ ] 排除方向有业务原因

## 5. 禁止项

- 不得为了凑足数量虚构产品；
- 不得将示范产品表述为真实在售产品；
- 不得承诺最低价、一定承保或一定赔付；
- 不得忽略营运、新能源和高频使用等关键信息；
- 不得把产品考点替代正式条款；
- 不得调用已停用的 `save_product` 写能力。

## 6. 异常处理

| 情形 | 处理 |
|---|---|
| 产品列表不可用 | 只输出保障缺口，不形成候选 |
| 产品详情缺失 | 不补造条款，提示人工核实 |
| 使用性质不明确 | 暂停正式匹配 |
| 产品字段冲突 | 标记冲突并联系产品责任人 |
| 客户要求正式报价 | 转报价系统或人工坐席 |

## 7. 留痕要求

保存客户和产品结果指纹、数据时间、候选和排除原因、规则版本及人工核实事项，不在普通审计日志保存完整客户画像。
