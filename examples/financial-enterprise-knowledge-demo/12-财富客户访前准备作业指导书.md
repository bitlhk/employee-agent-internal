# 财富客户访前准备作业指导书（演示）

> 文件编号：LG-WM-SOP-001
>
> 版本：V1.0
>
> 责任部门：财富管理部（演示）
>
> 生效日期：2026-08-01
>
> 适用岗位：财富经理
>
> 文件性质：演示参考资产，不代表任何真实银行制度

## 1. 目的与适用范围

本指导书用于规范财富经理在客户面谈、电话会议、季度回顾和重大产品到期沟通前的准备工作，确保客户资料使用符合授权范围，沟通内容基于当前业务数据和现行制度，并形成必要的内部留痕。

本指导书适用于存量财富客户的常规拜访和服务准备。投诉处理、可疑交易调查、重大风险事件和正式投资交易应执行对应专项流程，不得以访前准备替代。

## 2. 职责边界

财富经理负责：

- 明确会议目的、时间、参与人员和预期产出；
- 在本人授权范围内核验客户画像、持仓和待办；
- 识别需要进一步确认的事实和风险；
- 准备内部简报和沟通提纲；
- 会后按照 CRM 留痕要求记录结果。

财富经理不得：

- 查询本人无权服务的客户；
- 通过个人邮箱、个人网盘或普通群聊传递客户敏感信息；
- 根据历史记忆猜测客户当前持仓、风险等级或产品状态；
- 在风险测评失效或信息明显不足时形成正式产品推荐；
- 在客户确认前代替客户作出购买、赎回或签署决定。

## 3. 操作前置条件

开始访前准备前，应确认：

1. 当前人员以财富经理岗位身份登录；
2. 目标客户属于本人或当前团队授权服务范围；
3. 客户数据服务显示明确的数据截止时间；
4. 客户风险测评状态可核验；
5. 使用的制度和作业指引为当前有效版本；
6. 如涉及产品，只使用产品中心返回的当前在售和当前渠道可用信息。

任一必要条件无法确认时，应在简报中标记“待核实”，不得自行补写企业事实。

## 4. 标准操作步骤

### 4.1 明确会议任务

记录：

- 客户或潜在客户；
- 会议时间和方式；
- 参与人员；
- 本次会议目标；
- 用户明确要求的交付格式。

会议目标不明确时，优先确认是关系维护、产品到期、资产配置回顾、风险沟通还是其他事项。

### 4.2 核验客户身份和数据范围

先核验当前财富经理身份和客户归属，再读取客户详情。身份或归属校验失败时立即停止，不得通过客户姓名、手机号或其他方式绕过授权。

输出中使用客户称谓或脱敏标识，不展示身份证件号码、完整手机号、完整账号和家庭成员敏感信息。

### 4.3 获取当前客户现场

至少核验以下内容：

- 客户风险等级、测评日期和有效期；
- AUM 和主要持仓结构；
- 近期到期产品、流动性安排和重大变化；
- 最近一次沟通、未决事项和客户明确偏好；
- 已知的重要风险或服务事项。

客户余额、持仓、到期日期和风险评级必须来自当前授权业务数据。历史沟通记录只用于辅助理解，不得覆盖当前系统事实。

### 4.4 识别会议重点

根据当前数据形成 3 至 5 条会议重点。常见方向包括：

- 到期资金安排；
- 持仓集中度和流动性；
- 风险测评或客户信息更新；
- 既有产品的风险和服务事项；
- 客户目标、期限和偏好的变化；
- 上次沟通中尚未完成的事项。

会议重点应区分事实、待核实事项和建议，不得把推断写成客户已确认事实。

### 4.5 准备产品或配置讨论

只有在客户风险测评有效、需求信息足够且产品数据可用时，才准备产品或配置讨论。

如需筛选产品：

1. 获取当前可售产品；
2. 核验风险等级、期限、流动性、最低金额和销售渠道；
3. 执行适当性检查；
4. 排除不匹配、停售或渠道不可用产品；
5. 为候选产品准备风险揭示，不承诺收益。

访前简报中的候选产品仅用于财富经理内部准备，不代表客户已经同意或完成销售流程。

### 4.6 形成内部简报

内部简报至少包含：

1. 会议信息；
2. 客户概况；
3. 当前资产与持仓观察；
4. 风险测评和适当性状态；
5. 近期到期与待办；
6. 3 至 5 条谈话要点；
7. 待核实事项；
8. 建议的会后动作；
9. 数据时间和制度依据。

## 5. 必查项清单

交付访前简报前，逐项检查：

- [ ] 当前岗位和客户归属已核验
- [ ] 客户数据包含截止时间
- [ ] 风险测评状态已核验
- [ ] 持仓和到期信息来自授权业务系统
- [ ] 现行制度和 SOP 已通过有效性校验
- [ ] 产品事实来自当前产品系统
- [ ] 候选产品已完成适当性筛选
- [ ] 未展示非必要客户敏感字段
- [ ] 没有收益承诺、保本暗示或代客决策表达
- [ ] 待核实事项已单独列示

## 6. 禁止项

- 不得查询当前财富经理无权访问的客户；
- 不得用历史对话、网页搜索或模型常识补造客户事实和当前产品；
- 不得在风险测评、数据时间或关键字段未核实时形成正式推荐；
- 不得把内部访前简报自动发送给客户或写入外部系统；
- 不得在客户数据接口失败时将演示模板表述为真实客户结论。

## 7. 异常处理与升级

| 场景 | 处理方式 |
|---|---|
| 客户不属于当前授权范围 | 停止查询，联系客户归属或权限管理员 |
| 客户数据服务不可用 | 不形成正式客户结论，列出最小补充信息 |
| 风险测评过期 | 暂停正式产品推荐，先安排重新测评 |
| 产品服务不可用 | 可以完成客户和持仓复盘，不输出当前产品推荐 |
| 没有现行有效制度 | 说明依据不足，联系知识管理员确认现行版本 |
| 客户要求购买不匹配产品 | 不得绕过，按适当性制度处理并升级合规 |
| 发现疑似投诉、误导销售或数据泄露 | 停止普通访前流程，转相应专项流程 |

## 8. 会后留痕

会后应按照企业 CRM 规范记录：

- 实际会议时间和参与人员；
- 客户确认的需求和变化；
- 已完成的风险揭示；
- 提供的材料；
- 客户反馈和异议；
- 下一步责任人和完成时间。

创建 CRM 跟进任务、发送客户材料或写回业务系统属于业务动作，应经过平台权限、操作确认、幂等和审计控制。生成内部简报不代表已经完成 CRM 留痕。
