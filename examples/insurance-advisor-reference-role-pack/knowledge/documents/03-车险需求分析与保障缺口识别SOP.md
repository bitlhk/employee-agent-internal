# 车险需求分析与保障缺口识别 SOP（演示）

> 文件编号：LG-IA-SOP-002
> 版本：V1.0
> 归口部门：车险产品与客户经营部（演示）
> 生效日期：2026-08-11
> 密级：内部

## 1. 适用范围

用于保险顾问根据授权客户和车辆信息识别保障需求及待核实缺口。输出用于内部沟通准备，不等同于正式报价、承保建议或投保方案。

## 2. 最小输入

- 客户和车辆标识；
- 车辆类型、新能源属性和使用性质；
- 当前保障摘要；
- 出险或高风险信息摘要；
- 续保时间；
- 客户明确需求和预算关注点；
- 数据截止时间。

任何关键字段缺失时，应明确追问或列为待核实项。

## 3. 分析步骤

### 3.1 车辆和使用场景

区分家用、营运、商务、企业车队和其他场景。不得将网约车、货运或其他营运车辆按普通家用车辆假设处理。

### 3.2 当前保障

根据业务系统事实核对交强险、商业主险、第三者责任、车上人员、驾乘、新能源专属和相关附加保障。未返回的保障不能推定为已投保或未投保。

### 3.3 主要风险

从以下方向识别需要关注的风险：

- 车辆价值和维修成本；
- 日常使用频率和路况；
- 驾驶员及常乘人员；
- 新能源电池、充电和专属风险；
- 营运、高里程或复杂驾驶场景；
- 历史出险和如实告知事项；
- 客户对价格、服务和保障范围的偏好。

### 3.4 缺口分级

将结论分为：

1. 已确认缺口：有当前数据支持；
2. 可能缺口：需要补充资料；
3. 不适用：有明确事实排除；
4. 无法判断：数据源不可用或字段缺失。

不得把“可能缺口”写成确定事实。

### 3.5 形成沟通问题

围绕关键缺口形成少量、明确的问题，优先核实车辆用途、驾驶人员、现有保障、预算约束和服务偏好。不得诱导客户隐瞒事实以获得更低价格或不同承保条件。

## 4. 必查项

- [ ] 车辆使用性质来自客户或业务系统
- [ ] 当前保障来源和时间可定位
- [ ] 缺口结论区分确定与待核实
- [ ] 新能源和营运风险未被遗漏
- [ ] 未生成具体保费或承保结论
- [ ] 客户敏感字段按最小必要展示

## 5. 禁止项

- 不得根据职业、城市或车型做未经数据支持的风险定性；
- 不得把高风险客户直接描述为“骗保”或“拒保对象”；
- 不得建议隐瞒车辆用途、历史出险或其他重要事实；
- 不得把通用保险知识当作本企业当前产品事实；
- 不得在产品系统不可用时补造候选产品。

## 6. 异常与升级

| 情形 | 处理 |
|---|---|
| 使用性质与系统记录冲突 | 停止正式匹配，转业务支持核实 |
| 客户拒绝提供必要信息 | 仅提供通用说明，不形成正式建议 |
| 疑似隐瞒重要事实 | 提醒如实告知并转人工 |
| 客户要求核保结论 | 转核保专岗 |
| 数据冲突或过期 | 标记冲突，不选择性采用有利数据 |
