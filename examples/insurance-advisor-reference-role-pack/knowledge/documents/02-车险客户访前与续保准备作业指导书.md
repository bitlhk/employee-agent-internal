# 车险客户访前与续保准备作业指导书（演示）

> 文件编号：LG-IA-SOP-001
> 版本：V1.0
> 责任部门：车险客户经营部（演示）
> 生效日期：2026-08-11
> 适用岗位：保险顾问

## 1. 目的与范围

用于规范保险顾问在续保外呼、客户面谈和重点客户回访前的准备工作。投诉、理赔、核保和正式报价不属于本流程。

## 2. 前置条件

1. 当前用户以保险顾问岗位登录；
2. 客户属于本人或团队授权服务范围；
3. 客户服务显示明确的数据截止时间；
4. 车辆、续保和已有保障信息可以核验；
5. 使用的产品和岗位规范为当前版本。

条件不完整时在简报中标记“待核实”，不得根据客户类型或历史印象补写。

## 3. 标准步骤

### 3.1 明确沟通目标

确认本次任务是续保提醒、保障回顾、报价前信息核实、客户关系维护还是异议跟进。目标不清楚时先询问，不同时推进多个互相冲突的销售目标。

### 3.2 核验客户和车辆

通过客户 MCP 查询授权客户和完整画像，至少关注：

- 客户状态和最近联系情况；
- 车辆品牌、类型、新能源属性和数量；
- 家用、营运、商务或其他使用性质；
- 续保时间和已有保障；
- 出险和风险信息；
- 客户偏好、价格敏感度和沟通方式。

### 3.3 识别访前重点

根据已核验事实形成 3 至 5 个重点，例如：

- 续保时间和当前沟通状态；
- 车辆用途是否发生变化；
- 第三者责任、驾乘或新能源保障是否存在缺口；
- 是否需要正式报价或人工核保；
- 客户上次异议和本次建议回应方向。

### 3.4 查询产品和考点

只有客户和车辆信息达到最小完整度时才查询产品。产品名称、保障责任、适用人群和销售考点必须来自产品 MCP。没有当前报价时只准备产品解释和核实清单。

### 3.5 形成内部简报

简报至少包含：

1. 客户和车辆概况；
2. 续保状态；
3. 当前保障和待核实缺口；
4. 3 至 5 条谈话要点；
5. 禁止或谨慎表达；
6. 下一步动作；
7. 客户和产品数据时间。

## 4. 必查项

- [ ] 客户归属已核验
- [ ] 客户数据包含截止时间
- [ ] 车辆使用性质已确认或标记待核实
- [ ] 续保状态和已有保障来自业务数据
- [ ] 产品事实来自产品 MCP
- [ ] 未生成未经授权的正式报价
- [ ] 未展示完整手机号、证件号等非必要字段
- [ ] 投诉、核保和理赔事项已转专项流程

## 5. 禁止项

- 不得查询无权客户；
- 不得根据姓名猜测客户、车辆和保障；
- 不得把模板写成真实客户事实；
- 不得把示范产品写成当前真实在售产品；
- 不得自动向客户发送内部访前简报；
- 不得为了促成续保隐瞒免责、限制和待核实事项。

## 6. 异常处理

| 场景 | 处理方式 |
|---|---|
| 重名或模糊匹配 | 让用户确认客户标识，不自动选定 |
| 客户 MCP 不可用 | 返回最小输入清单和空白模板 |
| 产品 MCP 不可用 | 可以整理客户事实，不提供产品方向 |
| 车辆用途不明 | 列为首要核实问题 |
| 客户明确投诉 | 停止营销话术，进入投诉处理 |
| 客户要求正式报价 | 引导进入企业报价系统或人工坐席 |

## 7. 输出模板

```text
车险客户访前简报

一、客户与车辆概况
二、续保和当前保障状态
三、保障缺口与待核实事项
四、沟通目标
五、谈话要点
六、风险与合规提醒
七、下一步动作
八、数据时间和执行依据
```
