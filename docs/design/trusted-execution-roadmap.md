# 可信执行产品化路线

## 目标

把平台已有的岗位身份、工具授权、运行隔离和审计能力组织成一条可验证的执行链：

```text
用户指令 -> 岗位实例身份 -> 能力与数据范围 -> 受控执行 -> 结果 -> 审计凭据
```

目标不是增加安全口号，而是让普通用户能理解一次任务如何被约束，让管理员能检查约束是否真实生效。

## 设计原则

1. 只展示运行时真实返回的状态，不根据工具名称推断已经启用沙箱或审计。
2. 默认保持安静，不给低风险调用增加确认步骤。
3. 策略先可见、再观察、最后强制，避免一次性改变现有任务行为。
4. 强制策略必须失败关闭；运行条件不满足时不能静默降级到更高权限。
5. 用户界面不展示内部路径、完整租户标识、密钥或敏感策略细节。

## 第一阶段：可信状态可见

不修改后端调用链和授权逻辑，只消费现有事件字段：

- `adoptId`：表示事件已关联岗位实例，前端仅显示“实例身份已绑定”。
- `executor=sandbox`：显示“沙箱隔离”。
- `auditId`：显示“审计留痕”，不默认展示完整编号。
- `policyDenyReason`：显示“安全策略已阻断”，具体原因保留在工具详情中。

交付范围：

- 首页演示呈现“身份验证、数据范围、审计留痕”的执行过程。
- 对话工具详情增加执行凭据摘要。
- 没有可信状态数据时不展示摘要，不影响原有工具卡。

## 第二阶段：岗位安全基线

在现有岗位技能和 MCP baseline 之上增加只读策略视图，先不强制执行：

- 技能与 MCP 范围
- 数据范围来源
- 文件工作区范围
- 网络访问范围
- Shell、浏览器与外部发送能力
- 超时、CPU、内存和进程限制

管理员可查看岗位的有效策略、继承来源和配置差异。经过一段时间观察后，再为每项策略分别启用强制模式。

## 第三阶段：风险分级与失败关闭

- 低风险：自动执行并审计。
- 中风险：由管理员预授权，用户侧只展示状态。
- 高风险：删除、外部发送、发布和高敏数据操作要求本次确认。
- 禁止级：直接阻断并写入审计账本。

运行时沙箱、身份绑定或审计账本不满足强制条件时，对应高风险能力必须不可用，不能回退到宿主机或全局身份。

## 后续管理界面

不新增第三个同级“安全中心”导航，避免与现有入口重叠。三个页面按以下边界分工：

- 系统健康：回答服务、Runtime、数据库和渠道是否正常运行。
- 安全审计：回答发生了什么、由谁执行、是否成功，并提供查询和证据导出。
- 隔离审计：针对用户、实例和租户身份做数据边界核查与问题追踪。

“安全概览”作为安全审计页面顶部的汇总区，负责呈现当前安全态势，并链接到事件审计和隔离核查：

- 运行时隔离覆盖率
- MCP 身份绑定覆盖率
- 技能审核与风险分布
- 审计账本、失败队列和最近阻断事件
- 凭据加密与数据库权限状态
- 部署入口、HTTPS 和外部暴露检查

安全中心只聚合已有事实。没有探测数据的项目显示“未检查”，不得显示为“安全”。

## 发布门槛

- 第一阶段只涉及展示，可独立发布和回滚。
- 第二阶段必须先提供策略差异预览和兼容性测试。
- 第三阶段按能力逐项灰度，至少覆盖对话、技能、MCP、附件和定时任务回归测试。
- 任何宣传用语都应能对应到配置、运行状态或审计事件中的一项证据。
