# 审核意见、补件与任务留痕操作指引

**版本：V1.0**
**责任部门：运营管理部（演示）**

## 1. 审核意见结构

审核意见草稿应包含：

1. 审核范围和截止时间；
2. 已核验材料和关键字段；
3. 当前有效规则及版本；
4. 已通过的检查项；
5. 缺失、需补正和冲突项；
6. 异常线索及材料依据；
7. 疑点等级和人工复核建议；
8. 明确声明“草稿，不替代有权人员最终结论”。

## 2. 补件要求

每个补件项应说明：

- 缺少或不合格的材料；
- 对应规则和业务原因；
- 可接受的材料形式；
- 时间范围或有效期；
- 是否阻断后续审核；
- 责任人和期望完成时间。

不得只写“材料不全”或“请补充证明”。

## 3. 写入流程

```text
审核结果
  -> 形成安全摘要
  -> Policy Decision
  -> 用户确认
  -> 当前权限复核
  -> Idempotency
  -> 案件/任务系统
  -> Business Receipt
```

同一案件、同一疑点和同一轮审核使用相同幂等键时，只能生成一条任务。

## 4. Business Receipt

业务回执至少保存：

```text
capabilityId
externalTaskId
status
caseRefHash
approvalId
idempotencyKeyHash
executedAt
```

业务回执不保存完整客户材料和原始 Tool 参数。

## 5. 异常恢复

- 写入超时但结果未知：先按幂等键查询，不直接重试创建；
- 权限被撤销：拒绝执行并保留拒绝证据；
- 下游不可用：保留草稿和恢复建议，不声称任务已创建；
- 用户取消：不执行写入，已生成草稿可继续编辑；
- 回执缺失：标记执行状态未知并转人工核验。

## 6. 证据关系

Context Receipt 证明本次提供的材料、知识和能力；Response Evidence 证明最终文字引用的依据；Business Receipt 证明业务动作结果。三者独立保存并通过任务关联，不互相覆盖。
