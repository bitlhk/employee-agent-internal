# 岗位智能体体验与统一运营看板计划 V1

## 1. 目标

本计划先把现有岗位资产转化为一线用户可感知的工作入口，再将培训与日常运营指标统一纳入管理后台。它不新增第二套 Role、Skill、MCP 或 Golden Task 配置源。

## 2. 岗位覆盖

| 岗位 | 当前资产成熟度 | 本轮展示策略 |
|---|---|---|
| 财富经理 | Reference Role Pack，6 项 Golden Task | 展示标杆任务入口、业务进度和 Context Receipt |
| 保险顾问 | Reference Role Pack，6 项 Golden Task | 展示标杆任务入口、MCP 就绪状态和销售陪练 |
| 风控经理 | Reference Role Pack，6 项 Golden Task | 展示标杆任务入口、确定性预警判断和依据 |
| 审核专员 | Reference Role Pack，6 项 Golden Task | 展示材料受理、规则核验、疑点分级和人工复核闭环 |
| 投顾分析 | Reference Role Pack 已完成 | 6 项 Golden Task、10 份治理知识、Wind 数据门禁、研究输出边界与受控跟踪任务 |
| 通用助手 | 基础对话、文件和自定义 Skill | 突出 Skill 上传、安装和试用闭环 |

审核岗位继续沿用运行时 ID `credential-compliance` 和“审核专员”岗位名称；“智能审核”作为 Role Pack 产品表达，不额外创建岗位或运行时配置。投顾分析同样沿用 `investment-researcher`，不创建第二套岗位或金融数据能力。

## 3. 第一阶段：一线岗位体验

### 3.1 空会话岗位任务入口

- 仅在新会话无消息时展示，开始对话后退出主流程。
- 任务来自现有岗位资产语义；标杆岗位沿用 Golden Task ID。
- 任务使用实时 MCP 返回的客户、企业和产品，不绑定固定演示对象。
- 依赖连接不可用时明确标记，不把必然失败的任务作为可点击推荐。

### 3.2 Skill 上传闭环

上传成功后展示：

1. 技能包检查；
2. 兼容与安全检查；
3. 安装完成；
4. 企业运行环境同步；
5. 对话可用。

提供“一键试用”，自动选择该 Skill 并生成最小验证任务。兼容提示不等于安装失败。

### 3.3 业务化执行进度

默认展示“获取客户画像、核验现行制度、筛选适配产品、评估风险等级、创建跟进任务”等业务动作。底层 Tool 名、参数、耗时和审计信息保留在展开详情中。

### 3.4 任务依据

继续复用 Context Receipt：默认只显示依据数量、数据时间、引用、记忆和 Readiness；展开后显示业务现场、现行知识、治理判断、排除项和业务回执。

## 4. 第二阶段：统一运营监控

培训实时看板不单独建设，纳入管理端“运行监控”，替换难以解释的基础设施参数堆叠。Prometheus 继续作为数据源和技术诊断入口，不作为业务首页。

### 4.1 管理首页核心指标

- 当前在线用户、活跃岗位实例、运行中任务；
- Skill 上传数、安装成功率、首次调用率、调用成功率；
- MCP 可用率、关键岗位 MCP 降级数；
- 模型路由分布、TTFT P50/P95、端到端耗时 P50/P95；
- 权限弹窗率、未知工具率、任务失败率；
- AgentServer 期望/就绪/繁忙实例数与扩缩容事件。

### 4.2 下钻维度

- 时间：最近 15 分钟、1 小时、24 小时；
- 岗位：财富、保险、风控、审核、投顾、通用；
- 环境：上海集群、本地测试；
- 能力：Skill、MCP、模型、运行时；
- 错误：超时、限流、权限、工具不存在、上游不可用。

管理看板默认只展示汇总，不展示用户问题正文、客户数据或 Skill 文件内容。

## 5. 实施顺序

1. 岗位任务入口；
2. Skill 上传就绪与一键试用；
3. 业务化执行进度；
4. Context Receipt 轻量展示复核；
5. 统一运营指标契约和后台看板；
6. 智能审核 Reference Knowledge、Policy、Eval 与 Reference Role Pack（已完成）。
7. 投顾分析 Reference Knowledge、Wind 数据门禁、输出边界、Eval 与 Reference Role Pack（已完成）。
