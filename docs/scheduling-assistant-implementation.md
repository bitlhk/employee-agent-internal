## 当前实现（2026-10-19）

本节是现行规则。后面的历史记录用于追溯，涉及旧通知中心、日历协商入口、可发现性或强制忙闲复核的描述不再适用。

### 页面和创建行为

- 日历只承载日／周／月展示、增删改查和配置。人工保存直接复用 prepareWrite → confirmWrite，删除在详情中确认；不再跳转待办或通知中心。
- 日程可选择组织内参与人，详情展示组织者和参与人。会议与日程使用相同规则：创建、修改和改期不自动查询忙闲，不等待参与人回复。只有对话中用户要求查询／协商时才调用现有忙闲和协作工具；明确跳过时直接准备日程。
- 无组织的用户可以管理个人日历。搜索成员、添加参与人及跨人协作复用管理员维护的协作空间和成员身份；没有组织或身份停用时提示联系管理员。部门、团队只作为现有成员信息展示，不增加一套组织管理或人员统一服务。
- 组织成员搜索不依赖历史 discoverable 开关，也不要求先拥有助手。发起助手间协作时沿用现有助手身份、审批和执行权限。
- 参与人写入原 CalDAV 的 ORGANIZER / ATTENDEE，由 Nextcloud 同步。新参与人不要求 RSVP，外部服务原有的 PARTSTAT 保留，产品中不提供邀请状态流程。参与人不能通过本人同步副本编辑组织者的日程。

### 复用和权限

- 未配置日程协作接收策略时（包括没有独立协作设置的助手），默认使用“按已有授权自动接收”。显式保存的关闭、逐次批准或自动接收保持不变；其他任务类型沿用其原策略。仍由原本人日历授权 `autoAvailability` 决定能否自动查询忙闲，未授权时请求等待批准；分享结论与日历写入确认遵循原授权。本项通过统一策略读取实现，无需批量改写既有用户设置。
- 延用用户日历绑定、自动开通、凭据加密、草稿、执行锁、UID、ETag、操作回执和恢复任务。个人日程和直接会议共用这些能力，没有新增日程数据库或协作状态机。
- 创建及写入前校验参与人属于同一有效组织，地址从服务端绑定解析，客户端不能注入他人的邮箱或凭据。权限在草稿生成后被撤销也会拦截尚未发生的写入。
- 已经写入的操作先核对原回执，不因后续成员变动再写一次。日历服务按秒保存时间，重试也按秒比较。修改保留 UID、备注及 ETag 保护；网络结果不明继续核对同一草稿。
- 会议可用 event + participantIds + requestKey 直接准备；coordinationId 只用于兼容用户明确选择协商结果的场景。直接创建不需要先生成协调记录。
- 复用既有 MCP 参数兼容补丁，普通对话中的两种日程写入工具也保留显式空参与人数组，避免“移除所有参与人”被上游参数清理误变成“保持原参与人”。其他普通工具的处理规则不变。
- 日历编辑已有会议时同步其原有会议记录，避免后续改期／取消拿到旧内容。日历已经成功、后续记账失败时保留 unknown，供恢复逻辑继续核对。

- 确认、审批、忙闲回复、目标进度和级联操作放在原有聊天消息卡片中。已移除 Home 下方独立目标任务面板、日历通知中心、协商表单、群发布和独立日程聊天接口。
