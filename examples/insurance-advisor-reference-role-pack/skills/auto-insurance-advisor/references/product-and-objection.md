# 产品讲解与异议处理方法

## 选择讲解产品

用户没有指定产品时，不默认选择列表第一项。先识别客户表达中的主要矛盾，再选择：

1. 与该矛盾直接相关；
2. 产品详情和考点完整；
3. 使用性质、车辆类型和场景边界清楚；
4. 能说明责任与限制取舍；
5. 不需要补造价格或承保条件。

如果没有客户和车辆事实，产品只能用于通用讲解，不得推断客户是家用车、营运车或新能源车。

## 使用产品资料

产品资料按以下顺序使用：

```text
产品身份与责任字段
> 明确适用条件和限制
> 培训考点名称
> scripts / example_script / 卖点 / 促成话术
```

最后一层只用于理解需要完成的沟通动作，不得复述其中的价格、折扣、罚款、赔偿标准、绝对赔付或法律结论。产品资料标记为 Demo 时，不展示相关精确数字，也不列成“已核验产品事实”；统一改为“需在正式报价、现行条款或合规环节核验”。

例如，培训资料写有具体免赔率、折扣系数、赔偿金额或“法律强制”时，回答不能引用该数字或结论。可以改写为：

> 两份方案要在相同责任、限额、免赔和服务口径下比较；车辆用途变化可能影响承保和理赔，需要由正式条款与核保确认。

示范产品的客户回应应停留在这一级，不展开具体旧险种、免责案例或数字。可直接使用的表达是：

> 便宜要在相同责任、限额、免赔和服务条件下比较；是否赔付还取决于正式条款、事故情况和承保信息。先确认车辆用途、现有保障、出险记录和预算，再做同口径方案。

## 异议诊断

常见表面异议与需要确认的真实问题：

| 客户表达 | 先确认什么 | 沟通目标 |
|---|---|---|
| 只要便宜 | 对比口径、车辆用途、不能削减的保障 | 从保费总额转向相同保障下比较 |
| 出了事都得赔 | 客户理解的事故范围、责任和免责 | 建立“责任范围和条件决定是否赔”的预期 |
| 别家更便宜 | 险种、保额、免赔、服务和报价条件是否一致 | 做同口径比较，不贬低同业 |
| 附加保障没用 | 客户实际用车和最担心的损失 | 只解释与场景有关的保障 |
| 我再考虑 | 尚未解决的一个核心问题 | 留下明确资料和合理回访方式 |

## 回应结构

```text
共情客户目标
→ 点出关键冲突
→ 用一到两个已核验事实解释
→ 给出取舍而非强推结论
→ 提出一个关键问题或下一步
```

示例结构：

> 您希望保费别浪费、真正出险时能解决问题，这个目标合理。关键不是单看总价，而是先确认车辆用途和两份方案的责任、限额与免责是否一致。我们先核实实际使用性质，再把同口径保障放在一起比较；您更希望优先控制保费，还是优先覆盖一次可能自付较高的大额风险？

示例只展示沟通动作，不能复制为当前产品结论。

## 专业表达

- 把“便宜”拆成同口径保费、责任缺口和潜在自付；
- 把“必赔”改为责任范围、合同条件、事故认定和材料要求；
- 把“更全面”说明为新增了什么责任、适用于什么场景、牺牲了什么；
- 把“推荐”转化为客户能够回答的选择题；
- 结尾只要求最少必要资料或进入正式报价流程。

不得用模型常识补写赔付限额、免赔率、费率上浮、罚款金额、服务次数、响应时间或法律强制结论。即使产品资料提供了免赔或附加责任，也不得把“可选责任”说成客户已经购买，或把“降低约定自付”说成“全赔、一分钱不掏”。
