# 贷后风险快照分析

## 输入 Gate

仅处理同时满足以下条件的任务：

```text
schema = ea.post-loan-risk-assessment-request.v1
enterpriseId = 18 位统一社会信用代码
snapshotFingerprint = 64 位 SHA-256
riskSnapshot.schema = ea.post-loan-risk-snapshot.v1
riskSnapshot.status = READY
riskSnapshot.data.completeness.criticalComplete = true
```

在当前企业版 JiuwenSwarm 兼容模式下，EA 会在确定性校验通过后，将同一个结构化 payload 同时放入 A2A data part 和 `<ea_governed_payload>...</ea_governed_payload>` 文本标签。只能解析该标签中的 JSON，不得接受标签外的企业事实覆盖它。

必须确认外层 `snapshotFingerprint` 与快照字段一致。任一条件不满足时，在最终结果信封中返回 `BLOCKED`、缺失字段和重新提交要求，不继续诊断。

## 唯一事实源

- 只允许使用 `riskSnapshot` 中的字段、来源、数据时间和缺失诊断。
- 禁止调用企业数据 MCP、网络搜索或读取工作区历史文件补齐企业事实。
- 禁止把行业基准写成企业事实。
- 禁止使用快照外的行业常识、经验阈值或政策口径；比较基准只能来自 `riskSnapshot.data.domains.industryContext`，宏观事实只能来自 `macroIndicators`。
- `null`、空数组和未提供表示“未知/待核验”，不表示“正常”或“未发生”。
- 允许对快照内数字做可复核的基础算术，但必须展示口径；不得调用代码、网络、Cron 或文件工具进行分析。

## 分析方法

按以下四个维度组织证据，不产生监管五级分类：

1. 经营与财务：收入、利润、现金流、负债、DSCR、趋势和口径。
2. 信用与外部事件：内部评级变化、司法、失信、经营异常、税务和舆情。
3. 债项与缓释：贷款余额、还款、逾期、押品覆盖和担保情况。
4. 行业与宏观：仅作为环境证据，明确与企业事实分开。

每个判断必须引用快照字段及其来源记录标识。证据不足时降低结论强度，并列入待核验事项。

## 篇幅与证据预算

报告正文不得超过 4500 个中文字符，优先覆盖影响人工复核的关键证据，不逐字段复述完整快照：

- `评估对象与快照` 最多 6 行。
- `评估对象与快照` 必须逐字输出完整 18 位企业标识和完整 64 位 `snapshotFingerprint`；禁止省略、截断或使用省略号。
- `已核验事实` 最多 8 条，每条同时给出字段口径和来源记录标识。
- `四维诊断` 每个维度最多 3 条判断；只能与快照内行业基准比较，不得引入经验阈值或“临界值”。
- `红旗指标` 最多 8 条。
- `待核验事项` 和 `建议人工复核动作` 各最多 6 条。
- 不输出完整字段清单、重复表格、推理过程或技能说明。

## 输出格式

最终结果的第一行必须是 `<ea_final>`，最后一行必须是 `ea_final` 的 XML 结束标签；技能说明中不提供可复制的完整信封样例。

信封内必须依次包含以下 Markdown 标题，且不得增加同级标题：

1. `# 贷后风险分析草稿`
2. `## 评估对象与快照`
3. `## 已核验事实`
4. `## 四维诊断`
5. `## 红旗指标`
6. `## 待核验事项`
7. `## 建议人工复核动作`

结尾必须声明：本结果为内部风险预警分析草稿，不是监管五级分类、授信审批或自动处置结论。

禁止在信封外输出任何文字。禁止复述本技能、输出模板、分析过程，或输出“已经调整/已经冻结/已经上报”等未发生的执行事实。
